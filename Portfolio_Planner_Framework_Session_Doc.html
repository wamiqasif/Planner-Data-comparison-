Maven Project Setup

Created a dedicated project directory at ~/portfolio-planner-api-tests/. The home directory already contained other projects so an explicit subdirectory was used.

Key pom.xml decisions

  • rest-assured declared as compile scope (not test) so that Api1Client, Api2Client, and ApiResponse — which live in src/main/java — can import REST Assured classes.
  • All other test-utility dependencies (TestNG) remain test scope.
  • Compiler and Surefire plugins both set to Java 17.
  • Surefire points to testng.xml via <suiteXmlFiles>.

ConfigReader — three-layer resolution

  1. Environment variable (e.g. API1_BASE_URL overrides api1.base.url)
  2. Environment overlay file (config-uat.properties when ENV=uat)
  3. Base config.properties

Sensitive values (tokens, cookies) are accessed via getSensitiveEnv(String envVarName), which reads only from System.getenv() — never from any properties file.

ExcelReader numeric safety

Excel stores all numbers as double internally. ExcelReader.formatDouble() converts whole-number doubles to integer strings before Long.parseLong() — so 50000.0 → "50000", never "50000.0".

3API Client Layer

ApiResponse, Api1Client & Api2Client

ApiResponse — two factory methods

// Successful HTTP exchange (any status including 4xx/5xx):
ApiResponse.of(String apiLabel, Response response)

// Transport error (connection refused, timeout, DNS):
ApiResponse.ofError(String apiLabel, long elapsedMs, Exception e)
  → statusCode = -1, responseBody = ""

The getResponseBody() always returns the body — there is no status-code guard. 4xx/5xx bodies are captured fully.

Api1Client (JSON POST)

  • POST https://qaappapi.valueresearch.in/api/v1/planner/generate
  • Content-Type: application/json
  • Timeouts: connect 10s, read 30s (from ConfigReader)
  • Payload provided by caller — client does not build it
  • Any exception caught → returns ApiResponse.ofError()

Api2Client (multipart/form-data POST)

  • POST https://advappapi.valueresearchonline.com/api/v0/investment-plan/
  • Content-Type set automatically by REST Assured (includes boundary)
  • Each entry in the Map<String,String> form fields becomes one .multiPart(key, value) call
  • Any exception caught → returns ApiResponse.ofError()
Design rule: Clients never create payloads. They receive a pre-built JSON string or form-field map and execute exactly one HTTP call.
Integration smoke result: API-1 HTTP 200, API-2 HTTP 401 (expected — no credentials set)

6Normalization Layer

FieldMapping, Normalizers & ResponseNormalizer

CurrencyNormalizer

CurrencyNormalizer.parse("₹50,000")   → BigDecimal(50000)
CurrencyNormalizer.parse("1,00,000")  → BigDecimal(100000)   // Indian lakh
CurrencyNormalizer.parse("40.00%")    → BigDecimal(40.00)
CurrencyNormalizer.parse("50000")     → BigDecimal(50000)

Strips ₹$€£%, and whitespace; parses the remainder. Returns null for null/blank/unparseable input — never throws.

TransactionTypeNormalizer

normalize("sip")       → "SIP"
normalize("SIP")       → "SIP"
normalize("one_time")  → "ONE_TIME"
normalize("One-time")  → "ONE_TIME"
normalize("unknown")   → "UNKNOWN"   // uppercase pass-through

FundNameNormalizer

normalize("Alpha Fund Dir-G")    → "Alpha Fund Direct-G"
normalize("Beta Dir- G Fund")    → "Beta Direct-G Fund"
normalize("Already Direct-G")   → "Already Direct-G"  (unchanged)

Uses Pattern.compile("\\bDir-G\\b") (word boundary) to prevent partial-match replacement.

ResponseNormalizer

Applies all normalizers to a full ExtractedResponse and returns a new immutable instance:

  1. FundNameNormalizer.normalize(planName) on every fund
  2. BreakdownEntry.resolvePercentage() promotes percFmt strings to BigDecimal when the numeric field is absent
  3. Transaction legs already carry normalizedType — no extra work needed
Result: 42 normalization tests — all PASS

Mismatch structure

Mismatch {
  testCaseId   : "TC_001"
  fieldPath    : "funds_data.data[plan_id=PLAN_001].investment_amount"
  api1Value    : "82000"
  api2Value    : "75000"
  mismatchType : BUSINESS_VALUE_MISMATCH
  message      : "Values differ by 7000 (tolerance: 0.01)"
}

Comparison order (12 steps)

  1. HTTP status codes
  2. Extraction success check
  3. API response status string
  4. Fund count
  5. Fund matching by plan_id — MISSING_FIELD / EXTRA_FIELD for unmatched
  6. Category ID (per matched fund)
  7. Category name
  8. Fund name (with FundNameNormalizer)
  9. Investment amount (BigDecimal tolerance)
  10. Transaction types present
  11. Transaction amounts per type
  12. Breakdown category + percentage
Key constraint: Comparison never stops at first mismatch. ALL mismatches are collected before ComparisonResult is returned. Fund arrays are NEVER compared by index — always matched by plan_id.

ComparisonResult verdict

isPassed()  ← true when getFailingMismatchCount() == 0
             (NORMALIZATION_DIFFERENCE excluded from failing count)
getVerdict() ← "PASS" or "FAIL"

8TestNG Integration

ApiComparisonTest — DataProvider + Full Pipeline

Per-row pipeline

@DataProvider → ExcelReader.asDataProvider()     (Execute=Y rows only)

Step 3   →  Api1JsonPayloadBuilder.build(testData)
Step 4   →  Api2FormDataPayloadBuilder.build(testData)
Steps 5&6 →  Api1Client.post()  /  Api2Client.post()
Step 7   →  Log: HTTP status + response time
Step 8   →  Api1ResponseExtractor.extract(body)  /  Api2ResponseExtractor.extract(body)
Step 9   →  ResponseNormalizer.normalize(ext1)   /  ResponseNormalizer.normalize(ext2)
Steps 10-12 → ResponseComparator.compare(…)      ← ALL mismatches collected here
Step 13-14  → Assert.assertTrue(result.isPassed(), fullMismatchDetail)

Error handling

try {
    /* pipeline */
    rb.executionStatus("PASS" or "FAIL");
    Assert.assertTrue(result.isPassed(), message);
} catch (AssertionError ae) {
    throw ae;    // TestNG marks FAIL; result already recorded
} catch (Exception e) {
    rb.executionStatus("ERROR");
    Assert.fail("...");
} finally {
    ResultCollector.add(rb.build());  // always records
}

One failed DataProvider row does not stop remaining rows. TestNG continues naturally to the next Object[] element.

Generation guarantee

@AfterSuite(alwaysRun = true) on ApiComparisonTest.generateReport() ensures the report is always attempted, even when tests fail. Internal exceptions in the writer are caught and logged — they are never rethrown, so the report attempt never breaks the suite exit code further.

Input Excel (src/test/resources/testdata/PortfolioPlanner_TestData.xlsx) and output Excel (target/reports/API_Comparison_Result.xlsx) are on disjoint paths. The writer never reads the input file.

Known Limitations

1. TC_001 currently FAIL (credentials not set)

API-2 requires environment variables to be set before the full comparison can be exercised. Set the following before running:

export API2_AUTH_TOKEN_HEADER="<your-auth-token>"
export API2_JSON_API_KEY="<your-json-api-key>"
export API2_COOKIE="<your-session-cookie>"
# Optional:
export API1_AUTH_TOKEN="<api1-bearer-token>"

4. FundNameNormalizer is explicit-only

Currently handles one known substitution: Dir-G → Direct-G. Any new display difference discovered in production must be added explicitly to FundNameNormalizer.SUBSTITUTIONS. Fuzzy matching is intentionally disabled.

5. Single test case in Excel

PortfolioPlanner_TestData.xlsx currently contains one row (TC_001). QA engineers can add more rows directly in Excel; Execute=N rows are automatically skipped by ExcelReader.asDataProvider().

6. No parallel execution

The DataProvider is configured with parallel=false. For parallel API calls, the DataProvider can be changed to parallel=true and ResultCollector is already thread-safe (CopyOnWriteArrayList).
